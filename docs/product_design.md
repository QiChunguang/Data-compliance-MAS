# Product Design

ReguThink 的产品目标是让数据交易和数据治理场景中的合规审查更可解释、更容易复核。

## User Flow

1. 用户打开工作台。
2. 上传虚构或脱敏业务材料。
3. 提出合规审查问题。
4. 系统解析业务事实并识别处理活动。
5. 系统检索相关依据并识别风险。
6. 用户查看证据、知识图谱和报告草稿。
7. 人工复核后下载报告。

## Core Pages

- 首页/工作台：展示项目入口、对话框、材料上传和核心操作。
- 对话审查：围绕业务材料进行追问、确认和报告生成。
- 报告中心：展示报告章节、证据引用、下载入口和复核状态。
- 知识图谱：展示法规主题、风险类型、处理活动和证据关系。
- 人工复核 Gate：标记需要专业人员确认的结论和证据缺口。

## Design Principles

- 优先展示业务链路，不把内部调试信息暴露给用户。
- 把“模型生成内容”和“已绑定证据”区分开。
- 对高风险或证据不足结论给出人工复核提示。
- 展示版只使用脱敏示例，不展示真实业务材料。
